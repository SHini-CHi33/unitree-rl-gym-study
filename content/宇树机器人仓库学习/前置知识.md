## Vscode中指令

#### 🚀 第一步：环境初始化（每次重开终端必敲）

在 VS Code 打开新终端，**一行一行敲**，不然会报错：

```python
# 1. 激活你的专属环境
conda activate rl
# 2. 注入防报错的共享库路径
export LD_LIBRARY_PATH=$CONDA_PREFIX/lib:$LD_LIBRARY_PATH
# 3. 回到项目大本营（不管你在哪，这行带你回家）
cd ~/unitree_rl_gym

```
---

#### 🏃‍♂️ 第二步：跑训练模型（无头模式）

**注意：不管你在哪，先确保敲了 `cd ~/unitree_rl_gym` 回家！**

**1. 从头开始跑（新实验）：**

```python

python legged_gym/scripts/train.py --task=h1 --headless --num_envs=1024 --run_name 你的实验名字
```
_(比如 `--run_name Test_1`，跑完后 `logs/h1/` 里会出现带这个名字的文件夹)_

**2. 断点续训（接着之前的跑）：**

```python

python legged_gym/scripts/train.py --task=h1 --headless --num_envs=1024 --resume --load_run 之前的文件夹名 --checkpoint 400

```
_(注意替换 `之前的文件夹名` 和 `400`)_

---

#### 📈 第三步：看训练曲线（TensorBoard）

**再开一个新的终端**（或者在当前终端按 `Ctrl+C` 停下后）：
```python

cd ~/unitree_rl_gym
tensorboard --logdir=logs/

```
然后在浏览器打开 `http://localhost:6006`。

---

#### 🎥 第四步：导模型去 MuJoCo 看画面（核心四连招）

**1. 修改导出脚本（在 VS Code 里操作）**  
打开 `~/unitree_rl_gym/export_jit.py`，找到第 17 行：

```python

checkpoint = '/root/unitree_rl_gym/logs/h1/最新跑完的文件夹名/model_xxx.pt'

```
保存文件！

**2. 运行导出脚本（在终端操作）**

```
cd ~/unitree_rl_gym && python export_jit.py
```
_(跑完后，终端会打印出一个带 `exported/policies/policy.pt` 的路径，复制它)_

**3. 修改 MuJoCo 配置（在 VS Code 里操作）**  
打开 `~/unitree_rl_gym/deploy/deploy_mujoco/configs/h1.yaml`，把 `policy_path` 换成你刚才复制的路径：

```
policy_path: "/root/unitree_rl_gym/logs/h1/最新跑完的文件夹名/exported/policies/policy.pt"
```
保存文件！

**4. 看画面（在终端操作）**

```
cd ~/unitree_rl_gym/deploy/deploy_mujoco && python deploy_mujoco.py h1.yaml

```



对于 **H1（19个自由度）** 这种复杂的人形机器人，在 Isaac Gym 里，你的核心瓶颈**只有一个：8GB 显存**。同时，你的 **16GB 物理内存** 也会被 WSL2 吃掉一半。

综合来看：

- **官方推荐安全舒适区**：`--num_envs=1024` 或 `--num_envs=2048`（这是绝大多数论文里用的标准并行数）。
    
- **你的极限挑战区**：`--num_envs=4096`。
    
- **绝对爆显存区**：`--num_envs=8192`（大概率直接 OOM 报错退出）。
    

#### 🚀 怎么测出你的“极限值”？

不要直接一把梭哈 4096，很容易把 WSL2 跑崩导致电脑卡死。我们一步步来：

**第一步：先跑 1024（最稳的起飞点）**

```
python legged_gym/scripts/train.py --task=h1 --headless --num_envs=1024 --run_name test_1024
```
_跑起来后，看终端里的 `Computation: xxxx steps/s`，这个数字就是你的吞吐量。_

**第二步：开监控看显存（非常重要）** 

打开一个新的 Windows PowerShell (在开始中搜索) 窗口，输入：

```powershell
nvidia-smi -l 1
```
（这会让显存占用每秒刷新一次）。  
或者打开 Windows 自带的“任务管理器” -> “性能” -> “GPU”，看**专用 GPU 内存**。

- 如果显存占用在 **4GB ~ 6GB**，说明很安全，你可以按 `Ctrl+C` 停掉，加上去跑 2048。
    
- 如果显存已经飘红到 **7.5GB**，千万别再加了，再加就崩了。
    

**第三步：挑战 2048 或 4096**  

如果你测出来 1024 很轻松，直接上：

```
python legged_gym/scripts/train.py --task=h1 --headless --num_envs=2048 --run_name test_2048
```
